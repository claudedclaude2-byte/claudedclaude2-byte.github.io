Trust & scope

Know what was checked.
Know what still needs judgment.

Trust comes from explicit evidence and honest limits. A source link, a fingerprint and a human review decision each answer a different question.

01 / Preserve & explain

Data principles.

  • Preserve originals. Extraction and redaction create separate derived information; delivered revisions are retained.
  • Keep source locations attached. A supported citation has a defined source and location, rather than an unattributed summary.
  • Show unread material. Unavailable, unsupported or failed extraction remains visible; it is not silently treated as an empty record.
  • Keep reasons and state changes. Correction and review decisions should be inspectable later.
  • Require explicit authorization for live actions. A proposed follow-up, draft or prepared package is not permission to send or publish it.
  • Use synthetic material for public evaluation. Private records, credentials, case data and runtime databases stay out of public project discussions.

02 / Different evidence, different claims

What a mechanical pass means.

A dossier verifier can check its defined package structure, references, fingerprints, revisions and passage locations. Those checks help detect some broken or changed artifacts and make recipient review more repeatable.

Keep these questions separate

The tool does not establish legal admissibility, provide legal advice or certify a working bundle as court-ready. A reviewer must assess meaning, context, completeness and the applicable process.

03 / Decisions stay visible

Human review is its own gate.

Review records include a declared identity, a basis and an attestation. They refer to specific content. If that content changes, the decision cannot be treated as fresh approval of the changed revision.

Draft and not-reviewed states are valid descriptions of unfinished review. Mechanical checks must never turn them into a human-approved state. The operator approval ledger is a local file and is not cryptographically tamper-evident; its reliability depends on controlling access to that file. Reviewed OCR follows the same principle: a machine proposes text, and a person must compare, correct and confirm each applicable page.

Local identity is self-declared

The current pilot has no authenticated user system. A recorded name and attestation are supplied answers, not verified identity or proof of source reading.

04 / Practical data boundaries

What “local-first” means here.

The core database and ordinary evidence workflow are designed to run on the operator's computer. Local interfaces bind to loopback. A recipient-verification path can work offline after dependencies are installed.

Dependency installation may contact a configured package index. Explicit external source capture and authorized request delivery use network connections. Optional tools and integrations have their own requirements; local-first is not a blanket promise that every operation is offline.

The pilot's unauthenticated local interface should be used on a computer controlled by one operator. It is not a supported remote, public or multi-user service. A copied backup on the same machine also does not provide protection against losing that machine.

05 / A small glossary

Terms worth keeping precise.

Source record
A supplied or captured artifact being relied on. A copy and its recorded fingerprint are evidence of preserved bytes, not independent authenticity.
Provenance
Recorded information about the source, capture, relationship and subsequent use of an artifact or claim.
Claim
A statement attached to attributable evidence and a defined subject, open to review.
Derivative
A new output produced from a source, such as extracted text, a reviewed redaction or a working bundle.
Revision
A separately preserved version of delivered work, with changes and reasons kept visible.
Mechanical verification
Checking defined structural, reference, fingerprint and location rules.
Semantic support
A person's assessment of whether the cited source actually supports the statement in context.
Candidate
The exact software version or frozen artifact set to which a test or review result applies.

06 / Public presentation

This website is an explanation.

It contains public-facing project descriptions and an explicitly fictional workflow illustration. It does not include the private implementation, investigation records, operational database, source captures, credentials or overnight work logs.

There is no upload form, document processing, account system or analytics script here. The pages, fonts and scripts are served as static website assets. The hosting provider may maintain ordinary service logs under its own policies; following an external GitHub link takes you to GitHub.

The implementation repository remains private. This presentation does not publish a product download, grant an implementation license or advertise an approved real-client service. Future publication of runnable artifacts requires its own scope and review.
