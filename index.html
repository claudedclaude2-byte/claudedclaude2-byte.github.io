The problem

Records arrive in fragments.
Review needs a coherent trail.

A folder of documents is only the beginning.

Requests, responses, attachments, competing statements and corrected versions can become disconnected. Records Intelligence brings those pieces into a traceable workflow, while keeping missing information and unresolved questions explicit.

It is being built for people who need to explain what a record says, where it says it, and what still needs review: investigators, public-interest researchers, journalists and evidence reviewers.

The PDF pilot

A bounded matter, end to end.

The current evaluation route is deliberately small: one factual question, a defined set of PDFs, a draft review pack and one correction round.

  1. 01

    Define the question and expectations

    The operator supplies the matter, statements to check, exact passages, expected records and values that may conflict. The system does not invent the investigation question.

  2. 02

    Check the supplied folder

    See which files can be prepared, which cannot be read, and why. Empty or non-PDF intake is refused. Original inputs are preserved in the prepared revision.

  3. 03

    Prepare a source-linked review pack

    Inspect exact matches, possible matches, missing records, differing values, a chronology of recognized dates and links to source and bundle pages.

  4. 04

    Correct without rewriting history

    A complete corrected input set produces revision 2 with a reason. The earlier delivered revision remains available for comparison.

  5. 05

    Record a human review decision

    A reviewer records a name, basis and attestation against the content reviewed. Changed content makes that approval stale. A recorded identity or attestation is not independently authenticated.

The text mentions an attachment. That mention does not establish that the attachment was included in the supplied records.

Flagged for review

Keep the claim and the gap distinct.

The declared passage can be linked to the letter. The expected inspection record is absent from the fictional supplied set.

Useful next question

Was the inspection record omitted, withheld, or never created? The available passage alone does not answer that.

An exact text match supports the passage location. It does not independently prove that the repair happened.

Not reviewed

Make the unresolved decision visible.

The review state stays open until a person checks the relevant sources and records a basis. A follow-up can be drafted around the missing inspection record.

If a later revision adds the attachment, preserve the first revision and review the changed content. Mechanical verification cannot create human approval.

Common questions

What visitors should know.

Is Records Intelligence available as a public app?

It is in private development with a bounded pilot. There is no public product download, hosted account system or open enrollment on this site. The public website describes the project; it does not operate on records.

Does it use AI to decide what is true?

The described evidence checks are deterministic and source anchored. Optional development tools do not turn a text match or a contradiction flag into a factual judgment. Semantic/vector search is deferred.

Can I upload documents here?

This static website has no upload or investigation processing feature. The product's local workflows run on the operator's computer. Do not post private records, credentials or case details in public GitHub discussions.

What does a verifier pass establish?

Only the mechanical checks defined by that verifier: package structure, references, fingerprints, revisions and supported citation locations. It does not prove source authenticity, truth, completeness, lawful acquisition or legal admissibility.
