Product roadmap

Prove the workflow.
Then widen the scope.

A staged product direction, with an exit gate for each stage. Future work below is proposed, without release dates or a promise that every item will ship.

Development snapshot · October 2026

Core platform components exist. Final private pilot integration and installed acceptance are still being reconciled; the new synthetic demo and its independent final backup are in progress. This roadmap does not mark either as finished.

01

Close the private pilot completely

Finish startup and packaging integration, keep folder checks and unread states clear, and reconcile native, security, independent review and installed browser evidence.

Exit gate

The selected final candidate, package and installed files agree. Required checks have actual results; skips and findings are explained; the owner handoff names no unresolved required pilot gate.

Current work
02

Complete the synthetic investigation demonstration

Prepare a fictional walkthrough, a clear facilitator script, a reviewer checklist and a portable local package. Independently verify and back up the exact frozen kit.

Exit gate

The source version and artifact freeze agree; package and member fingerprints, re-extraction, readability and local links pass. The independent backup checks that same package. Any required refresh to the final pilot candidate is complete.

Current work
03

Make the project understandable

Publish a coherent project explanation, a professional GitHub profile, capability boundaries and a staged roadmap. Help potential reviewers recognize the value without exposing implementation data or private records.

Exit gate

Public claims match the documented scope; links and layouts work; the repository and investigation records stay private.

This presentation
04

Run a small guided evaluation

Use agreed fictional or explicitly authorized evaluation material. Observe onboarding, folder preparation, source inspection, correction and review. Improve the places where people hesitate or misunderstand the result.

Exit gate

Recorded operator observations explain the failures and improvements. Updated acceptance is tied to the changed candidate. Evaluation participants and scope are approved before work begins.

Proposed next
05

Strengthen the everyday workflow

Prioritize feedback-led onboarding, clearer troubleshooting, package portability, import clarity and stronger links between request gaps, follow-up questions and evidence review.

Exit gate

A change solves an observed problem, has a bounded scope and passes the relevant integrity and operator checks. New input formats are accepted individually. Coordinate-based scan redaction is a proposed capability: reviewed regions, actual pixel removal, and visual/extraction verification are required before accepting a derivative.

Proposed
06

Evaluate expansion deliberately

Consider collaboration, authentication, role boundaries, integrations or semantic retrieval only when evaluation evidence establishes the need. Benchmark added resource cost and retrieval quality before changing the architecture.

Exit gate

There is an explicit product decision, a measured benefit and appropriate access, data and review controls. A hosted or multi-user offering requires its own readiness decision.

Exploratory

Where the value can grow

The review loop is the product.

The strongest direction connects expected records, supplied evidence, source-linked findings, missing information and better follow-up questions. New features should make that loop easier to inspect and use.

Start with a real workflow need

Improve the point where a reviewer loses context or cannot explain a result.

Preserve the evidence trail

Keep sources, revisions, reasons and review states attached to the work.

Measure before expanding

Check usability, runtime cost and outcome quality before adopting heavier services or automation.

Participation

Useful feedback starts small.

Good contributions include a fictional evaluation question, a synthetic reproducible failure, an unclear workflow step, an accessibility issue or an explanation that a new reader misinterprets. Keep private records and client information out of public discussions.

Potential evaluation conversations can start through the builder's GitHub profile. There is no public beta signup, pricing or service commitment on this website.
