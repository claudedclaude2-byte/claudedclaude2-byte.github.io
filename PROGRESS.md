# Records Intelligence — development progress

Last checked: 2026-10-12.

The combined fictional pilot has completed automated Windows checks, and Windows remains the authoritative platform. Final technical acceptance remains open: the corrected candidate has not received an independent review, and its partial Linux/Docker verification is in progress. No release is authorized, and a public product download is not available.

## Completed

- [x] **Records and evidence foundations** — Records requests, response gaps, evidence search, source provenance and versioned dossier components are implemented in private development.
- [x] **PDF review and correction workflow** — Source-page citations, explicit match and unread states, a correction round and preserved earlier revisions are implemented in the fictional pilot.
- [x] **Combined Windows pilot** — Usability, packaging, source-wording and startup changes are combined in one candidate. Its recorded Windows suite completed with 6,332 tests passed and 424 skipped.
- [x] **Installed Windows journey** — The final candidate completed 484 installed tests, with three skipped, 13 smoke checks and 281 browser checks. These are automated results on the development machine.
- [x] **Reproducible package** — Two builds of the final fictional pilot produced identical package bytes. Installation and package identity were checked on the development machine.
- [x] **First-use rehearsal on a development machine** — The corrected candidate's package was unpacked, set up and checked in a new folder on a development machine, using fictional records only. The package checks, the one correction round and both recipient checks passed. A separate clean machine and participant feedback are still open, so this is not the clean-machine first use below, an acceptance result or a release.
- [x] **Windows verification of the repaired candidate** — Checked on Windows, on a development machine; not acceptance or release. The new candidate's full Windows test suite completed with 6,438 tests passed, 444 skipped and 0 failed. The candidate carries the repairs: explicit platform skips for the 9 Windows-only file-access cases (they still run on Windows), portable checks for the 2 shell cases, an opaque footer strip in the review bundle's page images (a partial fix, see In progress), and output-path boundary fixes for transcript-anchor output and '..' handling. The lint and security checks add no new findings (see the baseline item below), the dependency audit found 0 known vulnerabilities, and 21 of 21 deliberately introduced faults were caught by the tests. The package rebuilt twice with identical bytes and installed offline; the smoke test passed 13 of 13 checks, 490 installed tests passed (10 skipped), the headed-browser acceptance run passed 281 checks with 0 failed, and the recipient-route checks passed. One cleanup check failed: the optional installed test run leaves a temporary folder behind, a small follow-up that stays open. No independent review of the repairs has been run.
- [x] **Public project presentation** — This website and its public roadmap are hosted online. Product source and private research remain separate.

## Acceptance still open

- [ ] **Final technical review** — The previous candidate received a blocking review finding. The one planned review and one correction pass have been used. The correction pass has machine evidence, but no independent review of the corrected candidate has been run.
- [ ] **In progress: Linux and Docker verification (partial)** — The earlier Linux run on the corrected candidate passed 5,443 tests and held 11 known failures (9 Windows-only file-access cases and 2 shell-portability cases). The repairs for those cases are implemented on the new candidate and checked on Windows (see Completed), but the complete partial Linux run on the new candidate has no result yet: it was started once and stopped before any test ran, to stay within the test machine's free-memory limit, and it waits for enough free memory. Until it runs, the repairs are not confirmed on Linux, and the footer-strip fix stays partial: an annotation below a page's crop box and a crop box larger than the media box remain open. A partial platform check, not a substitute for the Windows suite, not acceptance or release.
- [ ] **In progress: Further repairs to the repaired candidate** — A further round of repairs is written but not yet checked as a whole, so the Windows results recorded here so far do not cover it. Review bundles now place stamps, highlights and notes on rotated pages where the original shows them, and they hide marks that lie wholly outside a page's visible area so that those marks cannot show in the footer strip; this addresses the two open footer-strip cases named in the Linux item. A mark that crosses the bottom edge of the visible area is still shown in part and stays open, and the text layer still includes text that a page hides outside its visible area. Delivery checks now recognise the same folder however a path is spelled (through folder links or '..'), on every platform. The pilot's self-check removes the temporary test folders it makes. The evidence health check and the evidence searches only read, and they report that there is nothing to check when there is no database. These repairs are not verified until the checks listed in Next milestones have run, and none of this is acceptance or release.
- [ ] **Lint and security baseline** — Repository-wide checks still retain existing findings. Recorded changes add no new findings in the checked code and security rules; this does not mean the entire repository is clean.
- [ ] **In progress: Automatic local tool startup and shutdown** — The shared runtime is implemented to start local tools when an operation needs them and close connections, temporary containers and ports after the last active owner finishes. Qualification is in progress, including interrupted jobs. Pilot acceptance and release remain open.
