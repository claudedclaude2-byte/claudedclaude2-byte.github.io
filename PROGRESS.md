# Records Intelligence — development progress

Last checked: 2026-10-16.

The combined fictional pilot has completed automated Windows checks, and Windows remains the authoritative platform. Final technical acceptance remains open: the corrected candidate has not received an independent review, and its partial Linux/Docker verification has passed on the development machine as a partial platform check only. No release is authorized, and a public product download is not available.

## Completed

- [x] **Records and evidence foundations** — Records requests, response gaps, evidence search, source provenance and versioned dossier components are implemented in private development.
- [x] **PDF review and correction workflow** — Source-page citations, explicit match and unread states, a correction round and preserved earlier revisions are implemented in the fictional pilot.
- [x] **Combined Windows pilot** — Usability, packaging, source-wording and startup changes are combined in one candidate. Its recorded Windows suite completed with 6,332 tests passed and 424 skipped.
- [x] **Installed Windows journey** — The final candidate completed 484 installed tests, with three skipped, 13 smoke checks and 281 browser checks. These are automated results on the development machine.
- [x] **Reproducible package** — Two builds of the final fictional pilot produced identical package bytes. Installation and package identity were checked on the development machine.
- [x] **First-use rehearsal on a development machine** — The corrected candidate's package was unpacked, set up and checked in a new folder on a development machine, using fictional records only. The package checks, the one correction round and both recipient checks passed. A separate clean machine and participant feedback are still open, so this is not the clean-machine first use below, an acceptance result or a release.
- [x] **Windows verification of the repaired candidate** — Checked on Windows, on a development machine; not acceptance or release. The final repair round's full Windows test suite completed with 6,686 tests passed, 458 skipped and 0 failed. The candidate carries the repairs: explicit platform skips for the 9 Windows-only file-access cases (they still run on Windows), portable checks for the 2 shell cases, an opaque footer strip in the review bundle's page images that also handles an annotation below a page's crop box and a crop box larger than the media box (a partial fix: an annotation that crosses the bottom edge of a page's visible area remains open; a documented limit remains: the text layer still includes text that a page hides outside its visible area), output-path boundary fixes for transcript-anchor output and '..' handling, now also at 4 further path sites, delivery checks that recognise the same folder however a path is spelled (through folder links or '..'), checked on Windows and not yet confirmed on Linux, review-bundle stamps, highlights and notes placed on rotated pages where the original shows them, except a free-text note that has no drawn appearance, evidence health checks and searches that only read and report that there is nothing to check when there is no database, and a check script that keeps the test run's temporary files in a folder of its own and removes it. The lint and security checks add no new findings (see the baseline item below), the dependency audit found 0 known vulnerabilities, and 209 of 209 deliberately introduced faults were caught by the tests. The package rebuilt twice with identical bytes and installed offline; the smoke test passed 13 of 13 checks, 571 installed tests passed (61 skipped), the headed-browser acceptance run passed 281 checks with 0 failed, and the recipient-route checks passed. The cleanup check that failed in the previous round now passes: the optional installed test run no longer leaves a temporary folder behind. No independent review of the repairs has been run.
- [x] **Windows verification of the business evaluation version** — Checked on Windows, on a development machine; not acceptance or release. The business evaluation version adds capacity profiles (named document limits, offered only once tested), a separate customer installation package, an updated operator guide and a fixed-scope evaluation offer that is still a draft. Its full Windows test suite completed with 8,027 tests passed, 470 skipped and 0 failed. The deliberately introduced faults were caught by the tests (538 of 538). The standard package rebuilt twice with identical bytes and installed offline on a development machine, and the separate customer package, assembled from a fixed list of files, was installed offline, used, stopped and uninstalled there (not on a clean machine). Document limits for the larger evaluation profile were measured on the real code, and that profile is offered only up to the limits that were measured. The evaluation offer is a draft only: it has not been sent or offered to anyone, and no software has been handed out. No independent review of this version has been run. The Linux confirmation is recorded in the next item. A first use on a clean machine is still open.
- [x] **Partial Linux verification of the business evaluation version** — Checked in a Linux container on a development machine; not acceptance or release. The business evaluation version, which carries the repairs of the repaired candidate, ran 138 of its 170 registered test files on Linux, with 6,135 tests passed, 334 skipped and 0 failed. The other 32 files test file-access features that exist only on Windows and run only there, so this is a partial platform check and not a substitute for the Windows suite. The 11 known failures of the earlier Linux run (9 Windows-only file-access cases and 2 shell-portability cases) no longer occur. A reduced set of the deliberately introduced faults was also run on Linux, and all 81 were caught by the tests. The Linux container was shut down afterwards. No independent review of this version has been run. The one open case of the footer-strip fix, a first use on a clean machine and the owner decisions on acceptance and release remain open.
- [x] **Checked: customer package builder reliability fixes** — Checked on Windows, on a development machine; not acceptance or release. A newer version of the business evaluation version fixes reliability problems in the customer package builder's own checks (its output printed every line ending twice, and a check that gets no answer, or a damaged list of the files to ship, ended in a crash report instead of a clear refusal) and adds a test that the start-up refuses an experimental document profile. Its full Windows test suite completed with 8,055 tests passed, 471 skipped and 0 failed. The deliberately introduced faults were caught by the tests (563 of 563, plus 4 of 4 skip checks). The customer package rebuilt twice with identical bytes and was installed, used, stopped and uninstalled on a development machine (59 of 59 checks; not a clean machine). The larger evaluation profile was measured again on this version (20 of 20 runs as required). A partial Linux check in a container on the same development machine ran 138 of the 170 registered test files, with 6,162 tests passed, 336 skipped and 0 failed; the other 32 files test file-access features that exist only on Windows and run only there, so this is a partial platform check and not a substitute for the Windows suite. A reduced set of the deliberately introduced faults was also run on Linux, and all 81 were caught by the tests. The Linux container was shut down afterwards. No independent review of this version has been run. Still open: a first use on a clean machine and the owner decisions on acceptance and release. No software has been handed out.

## Acceptance still open

- [ ] **Final technical review** — The previous candidate received a blocking review finding. The one planned review and one correction pass have been used. The correction pass has machine evidence, but no independent review of the corrected candidate has been run.
- [ ] **In progress: Business evaluation version** — The business evaluation version has passed its Windows checks, and a partial Linux check in a container, on a development machine (see Completed). The larger evaluation profile is offered only up to the limits that were measured. No independent review of this version has been run. Still open: a first use of the separate customer package on a clean machine, and the owner decisions on acceptance and release. The first-use check of the evaluation package in an isolated, offline Windows sandbox on the development machine has now run its full 70-step plan on the corrected candidate: 68 steps passed, 2 did not apply and none failed. A fresh, disposable Windows guest with networking switched off received only the package folder, an offline Python installer and the check scripts; offline setup, the fictional matter journey, the browser and recipient checks, stopping, restarting and uninstalling all passed. An earlier run, on the previous candidate, failed 2 of its 70 steps, both runs of the smoke test, because a long user path pushed files past the default Windows path-length limit of 260 characters, which the development machine did not show; the smoke test and the installation self-check now choose a folder that fits the limit, and the two steps now pass. The full Windows test run of the corrected candidate has also completed on the development machine, with 8,060 tests passed, 471 skipped and 0 failed, newer than the figures in the Completed items. A partial Linux run in a container, on that candidate plus two later changes to test code only, ran 138 of its 170 registered test files, with 6,169 tests passed, 337 skipped and 0 failed; the other 32 files test file-access features that exist only on Windows. The sandbox run used fictional data only, ran on the same machine and Windows build as the development work, covered one install route without customer security software, proxy or reboot, and the guest wrote its own receipts, so it is not a separate clean machine; this version stays in progress. The evaluation offer remains a draft that has not been sent or offered to anyone, no software has been handed out, and none of this is acceptance or release.
- [ ] **In progress: Path safety for workspace folders on Windows** — The safeguard for long workspace folder paths on Windows has been made on a development copy of the pilot and frozen as a candidate: the pilot now says plainly, before any work starts, when a workspace folder is too long for the default Windows limit of 260 characters, and it cleans up only the leftover temporary folders that it can prove it created itself. The full Windows checks of that frozen candidate have completed on the development machine: its test suite ran with 8,301 tests passed, 472 skipped and 0 failed, and 563 of 563 deliberately introduced faults were caught by the tests. The first-use run in an isolated, offline Windows sandbox and the Linux test run come next. These checks use fictional data only; the change has had no independent review, and none of this is acceptance or release.
- [ ] **Lint and security baseline** — Repository-wide checks still retain existing findings. Recorded changes add no new findings in the checked code and security rules; this does not mean the entire repository is clean.
- [ ] **In progress: Automatic local tool startup and shutdown** — The shared runtime is implemented to start local tools when an operation needs them and close connections, temporary containers and ports after the last active owner finishes. Qualification is in progress, including interrupted jobs. Pilot acceptance and release remain open.
